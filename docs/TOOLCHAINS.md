# 4.0 工具链操作与任务边界

## 编译结果

lint 与详细化分别返回 `success`、`failed`、`cancelled` 或 `skipped`。只有工具正常退出、
整个编译任务没有错误且诊断完整才算通过。当前文件的错误/警告数量仍单独提供，依赖
文件错误同时出现在 Problems 和任务总错误数中。工具启动失败、非零退出但无法识别的
日志、超时、日志写入失败均有明确说明；无 module 的详细化为跳过。

Vivado 的 `ERROR` 即使退出码为 0 也使 batch 失败，`CRITICAL WARNING` 为警告。
内部兼容返回值 `code` 会把这种语义失败映射为 -1，`exitCode` 保留真实退出码；工程树
操作不会再把失败脚本视为完成。`SVTOOLS_*` 项目标记由流式解析单独保存。

## 取消与产物

“停止仿真”从准备时就可用，覆盖探测、编译和 vvp；编译失败或取消后不会启动 vvp。
同一文档的检查会取代旧检查；新的仿真取代旧仿真。修改文档立即取消其进行中的 lint，
是否随后启动新检查仍由 lintOnChange 决定。关闭文档取消检查并释放其诊断；工具配置
变化取消旧配置任务，关闭扩展取消全部正在执行和排队的任务。

有工作区时 Icarus 与 xvlog 任务位于 `<所属工作区>/.svtools/tasks/<类型>-<随机名>/`；
单文件使用系统临时目录作为父目录。Vivado 日志目录为 `<Tcl所在目录>/tasks/vivado-*/`，
执行 cwd 与脚本路径保持原有约定。每个阶段写入 `01-probe.log`、`02-compiling.log`、
`01-xvlog.log`、`02-xelab.log`、`01-vivado.log` 等按阶段递增的独立文件，输出通道
显示本轮日志路径。任务完成后保留日志；lint/详细化只清理自己目录的其它内容，仿真
保留其 vvp 和任务产物供复查。各类任务默认按修改时间保留最近5个已交还的目录
（`svtools.tasks.retainedRuns`，0=不清理）。只有最后一个使用者释放占用后，目录才会
写入完成标记并参与封顶；其它窗口的活动任务和已打开电路图仍使用的快照不会被淘汰。
电路页面刷新或关闭时交还旧快照。同一父目录和类型的清理在宿主内串行执行。
旧版本、异常退出或归属标记无效的目录保守跳过，必要时可在停止相关工具后手动清理。

仿真继续在当前源码目录运行，保持相对 `$readmemh` 与 `$dumpfile` 行为。只有成功
运行且本轮文件元数据发生变化的 VCD/FST 才进入产物通知；失败的部分波形留在磁盘
供手动排查。内置查看器处理 VCD，FST 可交给配置的外部查看器；FSDB 开发已取消。
未保存文档的 lint 使用任务内快照，仿真使用磁盘内容并提示用户。

## 资源预算

| 资源 | 默认上限与行为 |
|---|---|
| 每个任务管理器的阶段并发 | 2 个进程；排队取消不启动工具 |
| Icarus/xvlog/xelab 编译阶段 | 每轮 120s；Icarus 工具探测 10s |
| vvp 与 Vivado batch 运行 | 沿用 simTimeoutMs / vivado.timeoutMs，0 为不限时 |
| 进程内存输出摘要 | stdout/stderr/合并输出分别保留最后 262144 个 UTF-16 码元 |
| 单行解析 | 65536 个码元；超长行保留头尾并标记不完整 |
| 结构化诊断 | 最多 2000 条，缺失单元最多 2000 个，共享 1048576 码元预算 |
| 完整阶段日志 | decoded UTF-8 流持续写盘，64KiB writer 高水位；背压暂停工具管道 |
| 输出通道 | 50ms 批量刷新，待刷新最多 65536 码元，可见正文约 1048576 码元 |
| Vivado 项目标记 | 最多 65536 码元；超限任务失败 |
| 终止与日志完成 | 终止后 2s 无退出事件显式失败；日志 flush 最多 5s |

长日志的尾部截断不丢失已捕获的早期错误和依赖。单行或诊断预算超限时不能确认通过，
完整已接收输出可在日志复查。正常结束等待日志关闭；取消时停止接收后续输出，保留
取消前已收到的内容。日志无法写入时终止工具并报告错误，不静默丢弃日志。
预算限制宿主缓存，不限制工具自己的内存，也不限制落盘日志的总大小。

## 开发验证

`npm test` 包含编辑器边界合同及真实 Node 协议子进程；它们验证阶段行为，不代替厂商
编译器。实际安装工具可用下列脚本复核，显式提供安装路径，不改用户工程：

```powershell
node scripts/verify-toolchains.js --iverilog <iverilog可执行文件> --vvp <vvp可执行文件> --cygwin <Cygwin-bin> --vivado <Vivado安装目录>
```

可以只提供 Icarus 或 Vivado；`--out` 指定验收父目录，默认在
`bin/toolchain-native-validation/run-*/` 新建目录。脚本实际执行编译、运行及错误判定，
生成 `report.json`、完整阶段日志和 VCD。

本轮尚未统一三种引擎的源文件/宏/top 编译计划，也未实现内容驱动的增量源码索引。
独立 xvlog 目录只在一次任务内使用 --incr，首次与跨任务编译可能比旧共享缓存更慢。
恢复跨任务缓存必须带源码、工具版本和配置键，避免重引入共享可写目录。
# 默认VCD目录

以下路径策略自本次开发构建起生效。

Icarus默认VCD集中在工作区`.svtools/vcd/`，无工作区时使用源码目录下的同一路径。默认文件名区分源文件、Top和引擎，避免不同目录的同名测试台覆盖；重复仿真保持稳定，写入前关闭并等待对应波形读取者退出。

实现使用vvp的默认dumpfile扩展参数，保持源码目录cwd和相对readmem语义，不修改RTL。显式`$dumpfile`及用户`simArgs`中的`-dumpfile=`继续优先，FST/LXT等非VCD格式沿用其原有规则。VCD仍需RTL执行`$dumpvars`，默认路径配置不等于自动启用记录。参数优先级见[Icarus官方说明](https://steveicarus.github.io/iverilog/usage/vvp_flags.html)。
