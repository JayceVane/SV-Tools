# 4.1 统一工程管理与多层级信号走向

活动栏保留一个 **SV Tools 工程** 入口。顶部切换器统一列出 Vivado 与 SV Tools 工程，来源由标签区分；视图下方切换文件和实例层级。

## 使用

1. 打开工作区，在工程切换器中选择已有 `.xpr`，或者创建 SV Tools 工程。
2. SV Tools 工程保存到工作区 `.svtools/projects/<名称>.json`。资源管理器右键 HDL 文件或文件夹，选择“添加到 SV Tools 工程…”。文件夹采用目录跟随，忽略工具生成目录和目录链接；文件保留原始路径。
3. 文件右键可设置工程顶层、仿真顶层、移动到设计／仿真集，以及移出工程。移出不删除磁盘文件。Vivado 工程仍通过原有 Tcl 执行管理操作和综合／实现／报告。
4. 保存参与分析的源码，在 RTL 编辑器中选中信号，右键选择“在工程中追踪所选信号”。第一次使用内置 Yosys 生成保留层级的工程模型；没有工程顶层时会要求指定。
5. 文件或模块实例名称右侧显示角色：`●` 为所选内部声明位置，`→` 为输出，`←` 为输入，`↔` 为双向，`?` 为未知方向。标记可组合，信号名、端口和位下标放在悬停提示里。
6. “实例层级”区分同模块的不同实例；“文件”聚合同文件实例的角色。点击实际实例回到经快照校验的源码位置。
7. 追踪后选择其它信号可复用模型更新标记，无须重新运行 Yosys 或 ELK。多个实例无法唯一选择时，使用右键明确上下文。“固定”保留当前追踪；源码修改、工程成员或顶层变化仍会撤销过期标记。

切换工程不改变原 Vivado top，不中断已有 Vivado 运行。展开状态和文件／实例显示方式按工程记忆。工程切换会释放追踪 Worker 并清除旧标记，返回工程后重新发起追踪；不把过往结果当作有效的新工程连接。

## 多层透传

追踪依次在模块局部网络和父子端口边界之间映射，支持上溯父级、进入兄弟实例、继续下探子模块。端口改名、HDL 升降序和切片／拼接由工具的实际位位置决定；模块名、信号同名和文件路径不作为连接证据。

例如 `top.u_a.rx → top.u_a.u_leaf.data`，以及叶模块输出改名回到父模块 `tx`，均能在同一次追踪中呈现。另一份 `top.u_b` 只有在实际连接到相同网络时才会标记。

这是一条信号的**网络连接与端口透传**。它不会自动穿越反相器、组合逻辑、寄存器或黑盒去猜测另一条信号；常量不按数值合并。双向、未知方向和多驱动有明确提示，箭头表示端口声明方向，不表示仿真时的实际驱动方向。

尚未执行追踪时，实例页沿用有界源码引用预览，并明确注明尚未详细化；执行后使用工具验证的实际实例树。工具优化掉的声明不能从源码映射。当前工程追踪使用 Yosys，Vivado 的工程操作与现有电路入口继续保留。

## 配置

```json
{
  "schemaVersion": 1,
  "name": "corelib",
  "root": "../..",
  "sources": ["src/top.sv"],
  "simulation": ["sim/tb_top.sv"],
  "folders": [{"path": "src/blocks", "fileset": "sources"}],
  "exclude": [],
  "top": "top",
  "simTop": "tb_top",
  "includeDirs": ["include"],
  "defines": ["SYNTHESIS"]
}
```

`root` 相对于配置文件目录，其余路径相对于 `root`。`sources` 与 `simulation` 是明确成员，优先于目录跟随中的排除；移动目录跟随的单个文件到仿真集时，会保存排除和新的明确成员。工程成员经共享源码服务提供给补全和现有工具链；工程 `includeDirs`、`defines` 用于本次工程信号模型生成，现有各工具自身的配置仍保留。
