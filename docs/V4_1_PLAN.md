# 4.1 开发计划：信号追踪

确认日期：2026-10-24。更新：2026-10-25。状态：M1位级查询与Worker接口已实现并验收，M2交互入口及后续阶段待开发。当前交付见[M1记录](V4_1_M1.md)。

当前稳定基线为 `v4.0.0`，对应 `master` 的 `3b6313e`。本计划中的 4.1 指正式发布 4.0 之后的新版本；历史 `V4_1_ALPHA*.md` 是已归入 4.0 的开发记录，不代表本计划已完成。

## 目标与使用场景

让用户从一个异常信号开始，查看驱动和负载，逐步展开附近电路，再关联对应源码及仿真波形。

例如 `o_valid_b` 未按预期拉高：在源码中选择该信号，执行“追踪驱动”，查看相关寄存器、MUX、数据输入和使能/复位路径；继续展开关注的分支，点击节点返回已有的源码位置。后续可将确认匹配的信号添加到波形，并查看游标时刻的值。

追踪依据是工具生成的真实电路连接。界面区分结构上的连接关系与经过证明的位级依赖；工具优化、参数化和 generate 展开后的电路不保证与每条 RTL 语句一一对应。

## 4.1 首版交付范围（P0）

| 能力 | 预期行为 |
|---|---|
| 源码追踪入口 | RTL 信号上右键选择“追踪驱动”或“追踪负载”；电路中的网络、引脚也可作为起点 |
| 起点确认 | 按声明作用域、设计实例、真实网络及位映射定位；同一源码模块有多个实例时明确选择上下文 |
| 局部逻辑锥 | 默认展示附近一层逻辑，按分支逐级展开或收起，不要求先布局整个大模块 |
| 时序与控制边界 | 明确标出寄存器边界，以及工具已确认的时钟、复位和使能；默认在时序边界停止自动扩展，继续追踪由用户显式触发 |
| 总线追踪 | 保留实际位组、切片、拼接、复制、升降序及非零起点；可追踪选定位，不把整条总线的连接都当成该位的连接 |
| 导航与关注对象 | 前进/返回、固定关注对象、恢复视口与展开状态；固定关注与固定节点位置分开处理 |
| 源码定位 | 沿用模型中已有且经过路径检查的位置；位置缺失或源文件变化时明确提示 |
| 连续展开体验 | 尽量保持已有节点的相对位置和用户相机，明确展示新增部分；布局确需变化时提供可理解的过渡 |

P0 形成“源码 → 局部电路 → 继续追踪 → 返回源码”的完整闭环，是 4.1 首版的发布门槛。

## 波形联动（P1，4.1 后续里程碑）

在 P0 通过验收后推进，不以未完成的波形联动阻塞 P0 独立交付。

1. 电路信号与已打开 VCD 的信号建立显式对应，允许选择设计实例与仿真根层级映射。
2. 从电路添加或定位波形行，从波形返回对应的电路追踪起点。
3. 在电路上按需显示 A 游标的精确值，再扩展 A/B 差异；没有事件、未 dump、X/Z 和失效映射分别显示。
4. 值查询复用现有波形 Worker 的压缩事件与按需查询，游标移动不触发电路重新生成或全图布局。

实例路径、位宽、范围及切片关系需要共同确认，不能仅凭同名关联。多候选由用户选择；优化删除或重命名后缺少可靠证据时，显示无法关联。电路结果与 VCD 可能来自不同源码或参数，关联中保留其来源上下文及人工确认状态，不宣称已经验证二者来自同一次构建。

## 实现原则与职责

复用现有 Yosys/Slang、Vivado 适配器、独立电路模型和 ELK.js + SVG 视图，不另建一套连接真相。以下是规划中的职责，文件名与具体 API 在实现时确定：

| 层次 | 职责与边界 |
|---|---|
| 源码适配 | 将编辑器选区解析为声明及实例候选，处理歧义与过期快照，不通过文本名称伪造网络 |
| Worker 内拓扑索引 | 以模块局部位 ID、端口方向和实例上下文建立驱动/负载关系；按模型版本复用，与页面已布局图的索引区分 |
| 追踪查询 | 独立纯查询处理方向、深度、位集合、时序边界、环路及容量；返回明确的停止/截断原因 |
| 展示投影与布局 | 将选中的局部子图变为展示对象，复用总线分支和符号规则，独立保存布局及展开状态 |
| 宿主与页面 | 宿主校验命令及源码定位，页面负责操作和渲染；查询、取消和关闭沿用现有会话所有权 |
| 后续波形桥接 | 负责实例/信号映射和小批量值查询，保持电路与波形各自的数据生命周期 |

复杂运算单元缺少可靠位依赖信息时，将候选输入作为保守范围并标明粒度；黑盒、未知方向、多驱动和缺失驱动保持显式边界。常量不与同值的其他常量视为同一物理网络；组合环路使用访问集合终止。

首版沿用已有模型总预算，局部追踪在完整模块布局之前执行。拓扑索引按设计世代和模块有界复用；若缓存查询结果，键还必须包含实例上下文、起点位集合及追踪选项。重新生成或来源变化使旧结果失效。取消和迟到响应不得覆盖当前视图，关闭会话释放索引、查询和布局资源。

Yosys 与 Vivado 使用同一查询语义。Vivado 当前适配结果是平坦 RTL，沿用其真实连接及实例路径；跨层展开只在模型提供明确端口映射时启用。

## 开发顺序与交付门槛

| 里程碑 | 主要工作 | 通过条件 |
|---|---|---|
| M1：连接与边界 | 建立位级拓扑索引和局部追踪查询；固定小型公开 RTL 及预期结果 | 驱动/负载、切片、复制、常量、寄存器、环路、黑盒、多驱动等结果可逐项核对；为大设计固定测量基线 |
| M2：追踪界面 | 接入源码/电路入口、逐级展开、前进返回、关注对象及稳定布局 | 真实 IDE 完成从源码开始、连续追踪并返回源码的流程；歧义、失败、取消和过期结果有明确行为 |
| M3：4.1 首版验收 | 真实工具、容量、交互、回归、文档和安装包验收 | P0 全部可用；4.0 功能回归通过；文档、公开夹具、测量条件和已知限制随交付保存 |
| M4：波形联动 | 实例映射、双向定位、A 值及后续 A/B 差异 | 层级重名、别名、切片、缺失 dump、不同来源及重仿真均不造成静默错配 |

M1已完成可验证查询、公开RTL和性能基线；M2将接入源码/电路追踪入口及连续展开。M1阶段保持扩展、native和CLI的4.0.0版本号，4.1安装包在后续交互及发布验收阶段准备。

## 验收要求

- 正确性：公开 RTL 覆盖组合/时序、多时钟域、MUX、存储器、总线及重复实例；对照真实 Yosys 输出，Vivado 沿用平坦模型边界核对，不用手绘图冒充工具结果。
- 规模：包含“完整模块超过现有布局预算，但其局部逻辑锥可查看”的用例；达到模型或局部预算时保留已得到的结果及明确的边界提示。
- 性能：固定语料记录首次索引、冷/热追踪、局部布局、内存，以及拖拽/缩放/选择的处理时间和帧间隔；验收前固定运行环境、重复次数及目标，不把单次测量或提高硬上限当作优化。
- 交互：明暗主题、键盘、取消、关闭、源码变更、重新生成及前进/返回均在实际 VS Code/Qoder 宿主验证；扩展包解包后复验关键流程。
- 回归：保持格式化字符/词法保全、golden、补全、模板生成、工具链、VCD 生命周期、二维 mem、总线展开和图片导出的既有合同；按实际改动运行相关 Rust、Node 和宿主检查。

## 后续候选与范围

Vivado IP 管理继续保留在 [路线图](ROADMAP.md)，优先级排在信号追踪之后。Vivado 层级保留、跨次生成缓存和更大规模按需载入按实际需求另行评估；本计划不承诺任意大网表、动态 RTL 调试器、CDC/时序签核或自动根因证明。FSDB 保持此前取消的决定。
