# env-runner-timeout-startup-race

> **发现方式**：新增Node24 CI矩阵时，旧工具链测试偶发失败。
> **定位耗时**：一次CI验收。
> **修复位置**：`test/toolchain_test.js`。

## 症状

```text
runner 超时会完成调用，并保留已输出日志
AssertionError [ERR_ASSERTION]: '' !== 'ready'
```

相同提交的Node22和本地Node24通过；远程Node24在400ms预算后正确终止，但尚未收到子进程正文。

## 排查过程

CI失败栈指向已有runner测试，尚未进入电路测试。该用例从进程启动开始计时，却假设子Node一定能在400ms内启动并输出`ready`。Windows并行回归与冷启动可超出该预算。生产runner在超时后停止接收正文符合已有取消合同；不能为了测试让启动阶段不计超时，也不能通过重跑掩盖竞态。

## 修复

拆开两个合同：用可控子进程流保证`ready`先到达，再触发真实定时器，验证输出保留和超时回调；另加真实Node进程验收，验证包括启动阶段在内的超时确实终止且有界完成，不假设正文已输出。既有真实进程手动停止用例仍在收到ready后停止，验证真实输出与取消。未更改生产超时、未延长预算或跳过用例。

## 教训

测试“保留已输出日志”必须先确立输出发生；短超时不构成子进程已就绪的证据。
