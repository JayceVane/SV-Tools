# logic-project-trace-top-context

> **发现方式**：用户选中仿真TB信号，侧边栏却报adder中用户类型／generate未解析。
> **定位耗时**：本轮定位与隔离宿主回归。
> **修复位置**：`src/project/trace-context.js`、`rtl-worker.js`、`flow-controller.js`。
> **修复提交**：`4302322`。

## 症状

用户在`sim/cdc/tb_cdc_hs_bits.sv`选择信号，收到：

```text
静态模型无法确定该声明的实例或位宽（宏、生成块、用户类型等可能未解析），请查看分析提示
adder.i：用户类型的位宽未知
adder.j：用户类型的位宽未知
adder：条件宏/生成作用域中的赋值未作为确定透传
adder.u_full_adder_idle：条件/生成作用域未展开
```

## 排查过程

TB的模块信号可由词法作用域识别，其位宽也可求值。追踪入口虽将当前TB所在文件集加入输入，却仍无条件执行`let top = project.top`，实际构建的是综合顶层adder。候选为空后拼接该模型提示，导致看起来像TB中存在这些错误。问题不在TB源文件，也与是否安装Yosys无关。

## 根因

输入集合包含某文件，不等于实例树可达其中模块。综合top、仿真top与当前编辑模块是不同上下文，不能把综合top当成所有追踪入口的顶层。

## 修复

按选中文件选择设计／仿真集与候选top，核验目标模块的文件、模块行号和实际实例路径。配置根不包含目标时，以所选模块建立独立追踪根，不改工程top。一次加载只解析一份RTL索引，候选根建模分别保留提示，丢弃无关根的诊断。模块已在实例树但信号位宽未知时仍保留该根及真实限制，不用换根伪造确定性。

同时默认首次选择即自动追踪；300ms防抖、串行合并、发布前校验选择世代。手动模式和固定均可取消待处理选择，自动错误只在侧边栏提示。回归包含首次选择、模型复用、连续选择、工程切换、脏文件、重复定义、仿真top和保留设计根；真实VS Code与Qoder扩展宿主另行验证。

补查发现原控制器清除结果时保留`pinned`，源码失效后固定按钮已隐藏，后续自动选择却仍被阻止。清除同时释放固定状态，并增加固定→清除→重新选择回归，避免只能靠手动追踪恢复。

## 教训

- 查询不到声明时，先检查实际分析根与来源身份，再判断解析能力。
- 文件集、顶层、实例路径共同定义上下文，不得仅按模块名或信号同名推测连接。
