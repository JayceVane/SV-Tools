# logic-source-catalog-invalidation-budget

> **发现方式**：M3解包VS Code验收，一个新建源文件就报容量超限。
> **修复位置**：`src/workspace/source-catalog.js`、`src/circuit/source-context.js`。
> **修复提交**：随4.1.0-beta.3候选提交。

## 症状

实际错误：`电路源码发现超过4096文件预算，请显式配置 sources`。

隔离工作区只有测试脚本新建的`trace_source.sv`。同一验收流程在其他启动时序下可以成功，说明不能只靠重新运行测试来处理。

## 根因

共享清单原先把`generation !== revision`与文件数量超限共同表示为`truncated`。源码新建事件或配置事件在异步`findFiles`期间到达时，即使只发现一个文件也会返回截断。电路调用方把所有截断都解释为4096文件超限。

观察器还会响应本来已从索引排除的`.svtools`产物，以及不影响文件集合的主题配置，扩大了时序窗口。

## 修复与边界

清单在世代变化后最多重读一次，仍不稳定就返回明确的`invalidated`标志并保持不完整状态。电路调用方先处理取消，再区分持续变化与容量超限，不能把不稳定清单伪装成完整结果。忽略被源策略排除的路径，仅相关源码配置触发配置失效。

新增确定性回归覆盖一次变更后取得新清单、连续失效有界退出、取消不影响其他消费者，以及工具产物/主题配置不清缓存。补全索引、共享清单与电路命令共29项通过；真实新建VS Code工作区的6项追踪流程通过。

## 教训

容量不足与读取快照失效是两种失败。共享服务必须保留原因，调用方不能只凭一个“不完整”布尔值推断文件数量。
