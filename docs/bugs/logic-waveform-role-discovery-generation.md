# logic-waveform-role-discovery-generation

> **发现方式**：发布审查中的真实Qoder波形宿主验收
> **定位耗时**：跨审查与修复两轮
> **修复位置**：`src/waveform/source-roles.js`、`host.js`、`worker.js`、`session.js`、`client.js`
> **修复提交**：未提交

## 症状

仅一个RTL文件、两个VCD信号也出现：

```text
方向未知：RTL候选或脏缓冲区超过扫描预算
AssertionError: undefined !== 'input'
```

## 排查过程

最初怀疑端口解析失效，但独立诊断能正确匹配2/2。原始用例和加入元数据落盘的用例多次失败，元数据明确显示“超预算”。
检查共享清单协议后发现，持续失效也会返回truncated。用一个真实RTL文件和可控的两次清单失效复现：文件数为1仍降级，稳定后重新收集则正确。
真实Qoder失败的每一次底层文件事件没有完整记录；根因路径由确定性用例证明，修复后再使用原始真实宿主用例验收，避免仅依赖带额外延时的诊断页面。

## 根因

清单为避免发布旧结果，在两次发现均遇变化后返回`invalidated:true,truncated:true`。方向上下文只保留truncated，把临时失效误作容量不足；方向又仅在打开时匹配，后续清单稳定也不恢复。

## 修复

- 方向收集保留失效原因，最多三轮重试并支持取消；真正的512文件、1MiB单文件、8MiB总量预算保持不变。
- 宿主合并源码变化，在原Worker中发送`roles`请求，只重新匹配RTL与信号角色，不重读VCD事件。
- 每轮核对世代，关闭/取消释放订阅与定时器。持续变化只提示暂不可用，稳定后再匹配。
- 页面接收独立roles消息，保留视窗、A/B游标、分组与派生位状态。

## 验证

单文件连续失效、真实超预算、取消、迟到结果及视图状态回归通过。修复后公开样包在VS Code1.143.0和Qoder API1.106.3的波形组均5项通过，含源码修改后的自动方向恢复与原Worker精确取值；源码失效链路和A/B读值也通过。

## 教训

1. truncated既可能是容量不足，也可能是取消或世代失效，消费者不能抹掉具体原因。
2. 元数据刷新应独立于数据加载，不能通过重新初始化整个页面来修复图标。
