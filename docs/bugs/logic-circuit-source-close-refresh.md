# logic-circuit-source-close-refresh

> **发现方式**：4.1严重缺陷排查的失败测试。
> **修复位置**：`src/circuit/source-watch.js`、`src/circuit/index.js`。
> **修复提交**：`fa0ecaaa196d1dc24c74002f5ffaae157281a652`。

## 症状与证据

编辑后在200ms防抖结束前关闭源码文档，旧观察器直接跳过`document.isClosed`，测试得到`0 !== 1`：旧图和读值没有失效。
此外生成入口在闭包中长期保留原TextDocument，关闭后刷新可能继续读取旧对象；令旧对象读取抛错的回归得到`1 !== 2`，第二轮生成没有发生。

## 根因

文档标签的生命周期与生成快照的生命周期不同。关闭标签不能证明生成输入没有变化，也不能让旧TextDocument代表下次生成的当前正文。旧观察器还只处理编辑器事件，未打开的输入被外部工具改写不会触发失效。

## 修复

防抖结束仍核对正文；无法读取时按不可核验处理。按输入目录复用磁盘监听，对实际输入做有界内容核对；同内容保存不误报，替换快照和关闭解除监听，世代检查阻止旧异步响应清空新事件。
Yosys和当前文件Vivado刷新重新取得已关闭文档，源码追踪起点同时复核当前正文。

目录监听的首轮Windows回归遇到真实native断言：

```text
Assertion failed: !_wcsnicmp(filename, dir, dirlen), file src\win\fs-event.c, line 72
```

临时目录使用8.3短路径，文件事件可能给出长路径；监听前使用`realpathSync.native`规范化，保留原输入键用于内容身份，相关真实临时目录回归恢复。

## 边界

监视对象仍是生成入口捕获的输入清单，不因此宣称网表与VCD同次构建，也不宣称覆盖任意宏展开、未捕获头文件或Vivado全工程的全部依赖。

## 教训

关闭文档、切换视图和换编译快照分别管理；对来源失效的修复应同时验证“及时失效”和“刷新后能恢复”。
