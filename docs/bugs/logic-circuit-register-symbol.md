# logic-circuit-register-symbol

> **发现方式**：用户提供sync_resetn RTL与电路截图。
> **定位耗时**：本轮定位与真实画布复验。
> **修复位置**：src/circuit/register-symbol.js、projection.js、renderer.js及client.js。

## 症状

$aldff的CLK接i_clk，ALOAD接i_rst_n，AD接0，D接1，但时钟三角位于左下角AD附近。所有端口都用空心圆；没有表达ALOAD低有效，标签只显示ALO…，难以确认是否为正确复位结构。

## 排查过程

1. 只读重新运行内置Slang/Yosys，检查原始JSON：CLK_POLARITY=1，ALOAD_POLARITY=0，五个端点连接全部正确。排除综合或源依赖接错。
2. 发现投影只传类别，不传参数语义；渲染器仅凭register类别固定绘制左下角三角，并把普通连接点绘制成空心圆。
3. 先增加会失败的时钟对齐、下降沿、控制气泡、缺失极性和真实ELK连接回归。实现后用用户实际网表检查浅深主题。
4. 首次截图发现普通引脚的短线与ELK连线之间出现小间隙。原因是ELK连线到端口外边缘，原有命中/标记取端口中心；新直线必须从外边缘延伸到单元边框。增加两侧端点回归并重新截图确认连续。

## 根因

单元分类不能替代时序语义。register同时涵盖边沿触发器和电平敏感锁存器；参数、引脚身份及几何锚点若在投影中丢失，通用图形就可能表达错误的电气含义。

## 修复与边界

已知Yosys字级单元通过纯展示模块解释原始参数，投影携带角色/极性/说明，SVG只按明确角色画时钟三角和低有效气泡。引脚及连接不改名、不优化，$aldff即使AD是0也保留异步装载原型；不伪装成工具生成的$adff。缺失或非法极性显示问号；Vivado和未知门级单元不按CLK名字猜时钟与极性。$adlatch补入寄存器分类。

单位测试覆盖两侧接线外边缘、正负触发沿、低高控制电平、LATCH及未知参数；实际用户RTL的6节点/5连线和源码SHA256只读核验通过。浏览器浅深主题验证标签不相交、气泡选择后仍为空心。

## 经验

端口命中中心与接线端点应区分。语义测试通过后仍需检查真实布局截图，零碎几何间隙很难仅凭DOM数量发现。
