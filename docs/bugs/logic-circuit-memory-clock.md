# 存储器未使用的时钟被画成有效X输入

2026-10-30。状态：已修复。定位于Yosys电路的展示投影、局部追踪和符号渲染。

## 特征与证据

用户的异步FIFO图中，`mem.RD_CLK` 接 `1'bx`，看起来丢失了 `i_clk_rd`。实际生成JSON显示 `RD_CLK_ENABLE=0`、`RD_CLK=["x"]`；输出寄存器 `$driver$o_data_rd.CLK` 与顶层 `i_clk_rd` 同为网表位12，数据经读使能MUX进入该寄存器。Yosys将这级结构表达为异步存储器读口和外部输出触发器，RTL读时钟没有接错。

根据 [Yosys存储器语义](https://yosyshq.readthedocs.io/projects/yosys/en/latest/cell/word_mem.html)，时钟使能为零时，该读口为异步读，相应CLK不使用。X是工具的占位值，不能直接改接成RTL时钟。

旧投影没有解释 `RD_CLK_ENABLE`，将原始连接全部当有效引脚建边并生成X常量。问题在展示缺少使用状态，而非适配器把真实时钟替换成X。

## 修复与边界

- `memory-symbol.js` 仅解释明确的Yosys `$mem` / `$mem_v2` 参数，复用现有符号语义边界；用户同名模块和未知器件不根据引脚名猜语义。
- 仅当整个时钟端口明确未使用时，从展示投影隐藏该端口及连线。同步使能下的X仍显示，其他单元使用的X不被全局删除。未知参数、多口同步/异步混合模式保留完整连接，并在属性描述各读写口。
- 存储器框内显示读写模式，独立标题行预留16px，时钟三角按明确有效的时钟及极性绘制；属性保留隐藏端口名称、宽度及原因。原始领域模型、位身份和外部输出寄存器连接不改。
- 局部追踪在生成独立常量之前过滤无效时钟，避免留下孤立X节点；底层追踪结果保持，PNG/SVG导出复用同一渲染器。

## 验证

- 修复前新增投影回归，隐藏RD_CLK、模式标签及异步写三项稳定失败；实现后通过。
- 覆盖同步X、其他逻辑X、未知参数、多口混合、旧版mem、用户同名模块、输出FF真实时钟、原模型不变及局部追踪常量。
- 真实内置Slang/Yosys生成最小双时钟存储器，经Worker和ELK布局后确认无效RD_CLK隐藏，输出寄存器CLK仍接真实读时钟。
- 用户实际网表只读复验为52节点、95连接；隐藏RD_CLK，输出CLK仍为位12。实际SVG渲染器的亮暗主题与黑白文档导出截图验证模式行和引脚无重叠。
