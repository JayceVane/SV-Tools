# logic-task-argument-columns

> **发现方式**：用户报告m_send形参默认值等号未对齐，并补充twakeup标量名称左移。
> **修复位置**：`src/native/src/align/task_func_param.rs`。

## 症状与定位

`tid = ...`的等号位于tkeep/tuser左侧；添加无位宽的`logic twakeup`后，名称又移到位宽列内。
原对齐器的正则将形参名之后的`= ...`整体放进comment尾部，名称填充只在紧跟逗号时执行。
无方向词的类型分支计算最大前缀只计类型长度，没有计入共享位宽列。

## 修复

先按现有规则生成声明行，再对已识别的形参行统计完整左侧列宽；无默认值的形参也参与。
复用共享最长匹配token扫描，在顶层单独的`=`处分开左侧和默认表达式；
括号/方括号/花括号中的表达式、字符串和注释中的伪等号都不作为列分隔符。
只替换等号两侧的布局空白，右侧表达式原文切片保留，完整管线仍执行字符与词法保全校验。
隐式input类型的最大前缀包括共享位宽列，以空白补齐标量，使名称列和portNameGap一致。

## 验证

原始m_send、含twakeup的m_send_with_wakeup都有人工期望golden；另验证函数默认值、
未初始化长名称、unpacked数组、嵌套比较、字符串/注释、Tab缩进、列间距、alignComma和inlineCompact配置。
测试同时检查完整格式化幂等及非布局字符守恒；单行和reindentOnly不引入列对齐。

## 教训

默认值不是注释，必须有独立的列契约；隐式方向参数与显式方向参数应遵循相同的列宽规则。
