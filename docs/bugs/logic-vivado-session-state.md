# Vivado 常驻会话的磁盘版本与失败写入

local.16 在受监视的 `.xci` 或 `.bd` 变化后尝试打开原工程。`openProject` 对仍存活的同路径会话直接返回，执行完动作又记录了新文件戳。会话中的工程仍来自旧版本，后续动作已无法靠文件戳发现这次变化。

地址编辑还有一条相似的残留路径。Vivado 2022.1.2 先接受 `range` 从 `64K` 改为 `32K`，随后拒绝超出主接口 aperture 的 offset，并报 `BD 41-70`。磁盘当时保持原样，之后新增无关端口时，`save_bd_design` 把内存中的 `32K` 一并保存。

文件戳变化时在同一个 Tcl 进程关闭并重开工程。读取使用动作开始时的文件戳，保留检测读期间外部保存的机会。生成的写入脚本返回失败时关闭会话，下一次动作从磁盘重新加载已经保存的状态。

`test/vivado_version_test.js` 验证重载、读取期间的外部保存及失败后的会话复用。`test/vivado_assets_test.js` 用真实 Vivado 复现越界偏移，核对失败前后的 `.bd`，随后添加子层级实例并确认地址范围仍为 `64K`。隔离工程中也实测了外部替换 `.bd` 后，常驻进程只重开一次且返回磁盘上的端口列表。
