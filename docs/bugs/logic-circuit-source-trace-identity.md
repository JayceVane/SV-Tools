# logic-circuit-source-trace-identity

> **发现方式**：M2真实Slang输出与源码入口集成验收。
> **定位阶段**：本轮M2实现及复查。
> **修复位置**：`src/circuit/trace-source.js`、`source-snapshots.js`。
> **修复提交**：随4.1 M2功能提交。

## 症状与证据

真实Slang网表保留模块`attributes.src`，但多数`netnames`没有独立声明位置；参数化重复实例还会生成不同的专用模块ID。

容错解析`always @(posedge clk) begin q <= r[2]; end`时，可能把右侧`r`额外识别为块内变量，其类型文本为`q<=`。直接取最近符号会找不到正确声明。

更危险的反例是模块声明`logic a`，task内部又声明`a`，或者访问`u.a`：如果忽略无法映射的局部声明，再向外查找同名网络，会静默定位到错误模块信号。

## 排查与根因

仅依赖每条网络的`src`不足以覆盖真实工具输出。按模块名和信号名补猜又无法区分作用域、条件编译或参数化实例。补全解析器用于容错编辑，部分符号只是候选事实，不能直接当成详细化后的电路声明证明。

静态位映射也必须保留原始声明下标；不能把展示图裁剪后的第0位当成原始信号的第0位。

## 修复与取舍

生成前采集编译输入内容指纹，生成后复核；起点联合核对快照、模块源码文件/行、合法声明作用域、真实网表网络和实际实例路径。存在工具单条位置时还要核对声明文件/行；条件编译缺少该证据时拒绝。

只丢弃`q<=`这类非法类型的容错伪声明；合法局部遮蔽阻止继续查找外层同名信号。层级/成员表达式要求从实际引脚进入。代价是部分复杂源码入口暂不支持，保留图上追踪能力而避免错误关联。

`circuit_trace_source_test.js`覆盖脏快照、重复实例、伪声明、条件编译、局部遮蔽和成员访问；真实Qoder/VS Code宿主验证源码修改后旧位置拒绝、刷新后重新定位。

## 教训

- 源码名称、容错符号和工具网络是不同事实，关联必须保留各自的证据。
- 无法映射的内层声明不能自动退回同名外层声明。
- 页面位置和源位置需要按生成快照验证，路径安全检查不能替代内容身份检查。
