# logic-circuit-bus-connections

> **发现方式**：用户提供cdc_1bit RTL及截图，LEVEL=2时D/Q看起来全是细线。
> **定位耗时**：本轮会话。
> **修复位置**：src/circuit/bus-routing.js、projection.js、graph-index.js、renderer.js。

## 症状

真实内置Slang/Yosys的数据为`D:n:4,n:6; Q:n:6,n:5; AD:c:1,c:1`。原展示图6节点/6连线，所有连线bits.length都是1；完整D/Q/AD端口各2位。i_bit、反馈及输出都接到相同的完整端口坐标，看不出各自的位位置。

## 排查过程

- 用用户源码在独立bin目录复现，核对生成数据和布局；领域端口位序正确，问题位于展示投影。
- 原算法按相同驱动端/接收端集合分组。Q[0]去D、Q[1]去o_bit，端点集合不同，确实应属于不同网络；不能把其中一条1bit切片标成2bit。
- 新增两位主干及显式连接条，分支保留真实位数与原网络ID。重复常量仍保持一位源，通过位置映射表达对AD两个位置的驱动。
- 全电路回归发现普通引脚原有局部高亮合同。保留其旧行为，仅对总线连接条或主干端口展开成员网络；避免无关行为变化。
- 区分同一位重复、向量重复和不规则重排。出现次数一致不能证明是向量复制，例如[a,b,b,a]必须显示逐位重排。

## 根因

位网络与向量端口不是同一层对象。按端点集合分组能保留连通性，却不能直接用同一个端点坐标表示向量中多个不同位置，也不能用去重后的常量网络宽度代替目标向量宽度。

## 修复

展示层在分组之后、ELK之前添加bus节点。完整主干保留原端口bits全部顺序与重复项；分支保持原网络的位数组，并记录每个分支位对应的完整端口位置（LSB=0）。主干位宽与分支位宽各自渲染，复制次数仅在位映射确实连续重复时标注。原领域模型、硬件单元数与容量限制不变。

选择分支时可高亮包含它的主干，但不递归选中主干的其它位。新增真实CDC源码的内置Slang→Worker→ELK回归，另覆盖切片、重排、常量重复、非恒定信号重复、预算及详情。新增节点增加布局规模，因此仍计入原展示预算，普通完整总线走快速路径。

## 教训

1. 检查每段线的bits，而不是只检查原端口宽度。
2. 位连接正确不等于向量关系表达清晰；需要独立的展示映射。
3. 不能用共享主干把不同位网络合成同一个可递归扩散的选择组。
