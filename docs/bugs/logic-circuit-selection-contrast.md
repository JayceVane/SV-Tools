# logic-circuit-selection-contrast

> **发现方式**：用户反馈亮色主题选中连线后消失。
> **定位耗时**：本轮会话。
> **修复位置**：src/circuit/view.css。

## 症状

旧beta.3页面在亮色背景注入`--vscode-focusBorder: #ffffff`后实际点击，连线仍有selected类且保留在DOM，计算stroke为`rgb(255, 255, 255)`；白底对比度1:1。焦点色为transparent时stroke为`rgba(0, 0, 0, 0)`，同样不可见。

## 排查过程

- 检查选择索引、DOM挂载及实际计算样式，选中对象和路径没有被删除。
- 原规则`.wire.selected .wireLine { stroke: var(--accent) }`，accent来自IDE的focusBorder。
- 原浏览器验收检查了选中类、线宽和主题切换，却没有注入IDE焦点色，也没有检查可见对比度，因此漏掉真实主题组合。
- 正式旧包在系统暗色偏好、IDE亮色主题下复现；其它焦点同色/透明组合也失败。修复后交叉系统明暗偏好与四种IDE主题类别，比较连线、位宽文字及相关端点的计算颜色。

## 根因

通用焦点边框并非电路选中标记的可见性合同。CSS `var(--vscode-focusBorder, fallback)`仅在变量缺失/无效时回退，已经定义的白色或透明值是合法颜色，不会触发回退。

## 修复

增加独立diagramActive颜色：亮色#005fb8、暗色#59c9ff、高对比暗色#ffff00。所有电路选中/悬停对象使用该颜色，按钮等普通IDE焦点样式继续使用原主题变量。实际页面交叉12种组合通过，当前测试背景中的最小对比度5.93:1；此数据不表示对任意自定义背景的保证。

本轮仅CSS与交付版本变更，选择及连接逻辑不变。验收探针及前后截图位于忽略的bin/，记录见docs/V4_BETA4.md。

## 教训

1. 变量定义合法，不等于适合当前语义或有足够对比度。
2. 主题验收需要注入宿主变量，并检查选中后的实际颜色，不能只检查class和stroke-width。
3. 系统明暗偏好与IDE主题类别要交叉验证。
