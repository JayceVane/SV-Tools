# logic-vivado-task-layout

> **发现方式**：用户报告`.svtools/vivado/actions`与`tasks`不断增加。
> **定位范围**：Vivado脚本准备、运行目录分配和历史淘汰作用域。
> **修复位置**：`src/vivado/script-task.js`、`index.js`、`projectTree.js`。
> **修复提交**：待提交后回填。

## 症状

用户工程只读检查得到57个`action-*`、10个旧`vivado-*`目录，总约1MiB。
一个典型旧动作包含`.Xil`、`simulate.tcl`、`xsim_run.tcl`和`tasks/vivado-*/01-vivado.log`。
即使`svtools.tasks.retainedRuns`采用默认5，也无法限制`actions`下的数量。

## 排查过程

现有通用任务管理器已经支持有归属的终态目录保留，不能直接认定缺少清理器。
进一步沿编辑器仿真和工程面板两条调用链发现：它们都用`mkdtemp(action-)`写脚本，
随后运行器将日志根设为`<该随机动作目录>/tasks`。每个父目录通常只有一个任务，
因此“每个父目录保留5次”永远不会触发；外层动作不属于任务所有权协议。
准备完成后取消或未找到工具，也可能留下未标记的外层目录。

## 根因

历史预算绑定了每次新建的随机父目录，预算的作用域与用户理解的“Vivado任务历史”不同。
单纯扫描删除`action-*`既绕过所有权协议，也无法保证其它窗口的活动输入不被移走。

## 修复

两条动作入口提交生成描述，不提前写动作目录。运行器创建`ToolTask`后，统一通过
`prepareVivadoScript`在所属工作区`.svtools/vivado/tasks/vivado-*`准备输入，日志使用
同一目录。准备前后核对工程／文件集，并检查取消信号。最终交还同一任务所有权，
脚本、日志和临时产物作为完整记录保留，再按同一根、同一类型的预算淘汰。
用户现有Tcl不改写／移动，原cwd保持；报告、工程`.runs/.sim`和波形不进入此清理。

旧目录没有完成标记，继续遵循[任务所有权协议](logic-task-retention-ownership.md)保守跳过，
不能以“创建较早”或“本窗口没有运行”推测可删除。

## 验证与教训

- 真实命令接线混合执行仿真／面板动作，将保留数设为2，确认6次执行后只保留最近2份新记录，且脚本／日志位于同一目录。
- 验证无归属旧目录不被删除，生成阶段取消仍交还目录并释放busy，已有用户Tcl保持内容与cwd。
- 有界清理的父目录必须是长期稳定的任务集合；输入脚本本身也应纳入生产任务的生命周期。

本轮用户另外明确选择“工具已停止后，仅保留最近5次并删除其余”。只读核验未发现相关工具进程，
对指定两个根的67份旧记录生成文件指纹与删除计划；边界、目录链接、进程和指纹复核后删除62份，
保留的5份全部指纹不变，释放1,023,971字节。该操作属于本轮明确授权的旧数据整理，
不等于插件会自动删除无完成标记的目录；计划和执行记录保存在本地`bin/vivado-legacy-cleanup-*.json`。
