# logic-circuit-trace-picker-generation

> **发现方式**：接入电路EDA视图前，复核上一轮审查的并发问题。
> **定位耗时**：本轮约15分钟，使用延迟Promise稳定重现。
> **修复位置**：`src/circuit/trace-controller.js` / `begin`。
> **修复提交**：未提交。

## 症状

先打开信号或实例选择框，再启动一次新的追踪。新追踪仍在计算时，关闭旧选择框会
发送`navigation.busy=false`，让取消入口隐藏；实际布局请求尚未完成。

## 排查过程

1. 既有测试覆盖旧布局响应迟到，但没有覆盖旧选择框取消。
2. 分别延迟`chooseSignal`和`chooseContext`，让新布局保持在途，再令旧选择返回null。
3. 发现`begin`在检查操作代次之前调用`settleBusy`，旧选择清理了共享busy。
4. 新增两种选择框的回归：旧选择取消后busy和最近一次页面通知都必须保持true，
   新布局完成之后才变为false。

## 根因

操作代次保护只覆盖正常选择返回后的渲染路径。取消分支同样会写共享状态，
却绕过了代次及设计身份核验；因此“结束旧操作”被错误地实现成“结束当前操作”。

## 修复

每个异步选择返回后，先校验关闭状态、操作代次和设计身份，再处理取消或继续。
当前操作正常取消仍执行原有busy清理；过期选择不发布状态。

## 教训

- 并发保护必须覆盖取消、失败及清理路径，不能只保护成功结果。
- 页面按钮状态与后台任务生命周期应由同一有效操作拥有。
