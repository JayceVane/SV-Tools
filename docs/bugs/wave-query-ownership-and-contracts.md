# 波形查询的分页、条件与会话所有权

本轮复现范围为 M4 CLI 与 Rust/wellen 后端。回归位于 `test/wave_service_test.js`、`test/waveform_stream_test.js`，真实 FST/VCD 夹具及其生成源码位于 `test/fixtures/waveform/`。

`sample` 曾在 JS 再次实现条件和翻页：只读取输出列，导致未输出的条件信号被当成空值，`q != d` 产生误报；已读取但尚未返回的采样沿又被 `t+1` 游标越过。现在条件及分页统一交给 Rust，条件信号独立加载，内部游标表示最后已返回采样，对外闭区间 `--from` 采用该游标加 1。

`diff` 曾把第一个遍历到的差异当作首差异。两信号分别在 50、10 tick 开始不同，会错误报告 50。现在按整数时间和路径排序，用有界最大堆保留全局最早 N 条，`firstDiff` 独立于输出条数。

worker 取消加载时，`close` 消息可能先于异步 open 返回，旧逻辑只释放当时已存在的句柄，晚到句柄泄漏。现在关闭先停止接收新查询，等全部在途请求完成后释放句柄，再自然退出；`dispose` 等待真实 exit，不再因超时强杀仍有原生任务的 worker。解析不可中断，取消会立即拒绝调用方请求，资源回收仍需等当前解析结束。打开后资源校验失败也立即释放。

CLI 的文件路径→句柄表只能在重开同一路径时释放旧值，查询不同文件会持续累积，也可能在同文件并发操作中关闭另一请求的句柄。现在每个操作独立持有句柄，以 finally 覆盖成功、失败及第二文件打开失败；直接调用 `openTrace` 的内部使用者须调用返回对象的幂等 `close()`。

FST 没有 VCD 的 `$var` 符号。以前退回 VarRef 声明序号，把 `tb.q` 和 `tb.dut.q` 的同信号别名误判为不同信号；现在使用实际 SignalRef。条件右值也按信号身份判重，保留不同信号的真实歧义。

视窗以前把整条信号历史解码成临时事件字符串数组，再做像素桶查询。现在直接二分 wellen 的已有时间索引，只解码起点及各桶首末事件，保留密集事件计数。性能验证应固定同一窗口、信号、输出规模并区分首次按需加载与后续查询，不能用文件打开速度代替交互性能。

本轮性能复验：同一百万事件、约 11 MB 的单信号记录，末尾 10 tick 窗口仍返回 9 条事件。旧实现复用查询约 141 ms；修复后首次信号装载约 5.5 ms，复用查询低于 0.1 ms。另以 100 个 32 位递增计数器生成约 100/500 MiB VCD，分别包含 277.5 万/1382.5 万事件；8 信号窄窗口复用查询约 1 ms，精确取值及关闭后句柄归零均通过。数字是本机该合成负载的测量，不代表任意信号规模的性能保证。项目现有 2 万信号、4000 别名语料的取值、沿定位和 dense 标记也通过。
