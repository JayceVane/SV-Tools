# logic-waveform-scientific-label-clipping

> **发现方式**：真实浏览器查看 FP32/TF32 非正规数，数值缩略丢失指数。
> **定位范围**：本轮浮点显示与 Canvas 实际渲染验收。
> **修复位置**：`src/waveform/renderer.js` / `text`。

## 症状

100ns 宽的总线段显示 `1.401298…`，实际值是 `1.401298464324817e-45`。
浮点解码正确，标签却无法表达数量级；同样的截断会影响名称栏 A/B 读值。

## 排查过程

1. 解码测试先对照 DataView，并穷举 FP16/BF16/E3M4，排除位域与数值计算错误。
2. 去掉矩形标签底色后，在真实 Canvas 发现极小数的末尾指数丢失。
3. 普通末尾加省略号按字符串长度裁剪，不知道指数是数值语义的一部分。
4. 修改共享文字函数，再用真实页面检查最小非正规数及明暗主题。

## 根因

数值字符串和普通名称共用前缀缩略。科学计数法的数量级位于字符串末尾，
保留前缀会丢掉指数；Canvas 的 `maxWidth` 又会横向压缩字形，不能解决可读性。
窄时间段和 A/B 名称栏都容易触发，单独测试解码无法发现此问题。

## 修复

识别 `^([+-]?\d+(?:\.\d+)?)([eE][+-]?\d+)$`，保留完整指数后缀，
只在尾数小数部分缩略，并测量实际字宽。典型结果为 `1.401…e-45`。
完整符号、整数部分、指数及省略号无法放下时不画该标签；宽段保留完整值。
绘制使用自然字形，不再向 `fillText` 传入压缩宽度。

## 教训

- 数值缩略要保留符号与数量级，不能只满足字符串宽度。
- 解码合同与 Canvas 绘制合同各自必要，真实窗口仍能发现组合问题。
- 不为填满窄段牺牲数值含义，完整 A/B 读值是精确检查的入口。
