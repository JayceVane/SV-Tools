# compat-header-template-multiline

> **发现方式**：用户反馈文件头不能使用文件模板，设置中粘贴多行后只剩一行。
> **定位耗时**：本轮约20分钟，包含真实宿主与多根工作区验收。
> **修复位置**：`package.json`、`src/editor/header-template.js`、`src/editor/commands.js`。

## 症状

`svtools.headerTemplate` 在设置界面只显示单行输入框，多行文本粘贴时丢换行。
没有独立文件路径设置，填写模板路径只会把路径文本本身插入源码。
beta.14的发布审查未覆盖这两个入口问题。

## 排查过程

先检查Rust `generate_header_template`：它只替换占位符，并不压平实际换行。
已有测试直接把带LF的字符串交给命令，能通过，但没有验证贡献配置的输入控件。
[VS Code配置贡献文档](https://code.visualstudio.com/api/references/contribution-points#contributesconfiguration)说明字符串需设置 `editPresentation: "multilineText"` 才使用多行控件；旧清单未声明。
新增的7项回归在旧实现全部失败，覆盖控件、资源作用域、文件读取、路径和末尾换行。

## 根因

配置输入与生成器之间的契约缺失：单行控件在模板进入生成器前已移除换行，生成器无法恢复；
原命令只读取字符串配置，也没有外部文件的读取和错误处理。若模板以 `//` 结尾且没有LF，原文件第一行会与注释粘连。

## 修复

内联配置声明多行控件，新增资源作用域的 `headerTemplateFile`。优先级为文件、内联、内置；
相对路径归属当前文档工作区，工作区外使用源码目录。通过 `workspace.fs` 每次读取，并严格验证UTF-8。
允许UTF-8 BOM，统一CR/LF后保留内部空行及已有末尾空行，缺少末尾换行才补一行。
显式文件缺失、空白或编码无效时拒绝插入，不以默认模板掩盖配置错误。

不全局解码字面 `\n`/`\t`：这会破坏模板中的Windows路径和代码示例。
`settings.json` 中的JSON转义由宿主解码，多行设置框和模板文件则使用真实换行。
已经压平的内容没有可靠行边界，升级后应重新粘贴，而非猜测恢复。

## 验证与教训

编辑器单测、真实VS Code与Qoder的配置落盘/占位符/NAPI插入/撤销、BOM/中文路径/CRLF、
修改后重读、三类文件错误以及双根工作区同名模板隔离均覆盖。

生成器收到正确字符串的单测，不能替代配置控件与实际持久化入口验证。
模板加载与原生占位符替换分开，使路径、编码和配置优先级只在编辑器适配层处理。
