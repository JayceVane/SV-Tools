# logic-completion-discovery-race

> **发现方式**：beta.7 真实 Qoder 扩展宿主，补全验收首次失败。
> **定位耗时**：约二十分钟，两个独立文件事件问题。
> **修复位置**：`src/editor/completion/index.js`、`src/workspace/source-catalog.js`。

## 症状

首次真实宿主出现：

```text
COMPLETION_HOST_CHECK_FAILED 超过 30 行的实例端口与参数，已连接项去重: 缺少补全项 port_89
```

候选里有当前实例已连接的 `port_0` 到 `port_69`，却没有被例化模块的完整端口。
第二轮出现：

```text
文件事件处理后补全结果仍未满足条件：external_word
```

工作区外 includePaths 新建的类型迟迟不出现；旧类型仍存在。

## 排查过程

1. 检查夹具：`long_leaf.sv` 真实定义90个端口，磁盘文件完整，端口语法合同正常。
2. 候选退回普通可见符号，说明缺少工程模块事实，不能靠扩大端口向前扫描行数解决。
3. 在共享清单通知恰逢首次异步读取时注入事件，稳定复现不完整 snapshot。
4. 修复后端口验收通过，外部 include 新文件验收失败；确认 RelativePattern 监听器已收到事件，
   但它只使补全自身索引失效，共享发现仍在10秒 TTL 内返回旧路径。
5. 增加清单和补全索引联合测试，让外部目录创建事件走真实缓存边界。

## 根因

异步读取途中 generation 改变时，旧扫描会停止，snapshot 却只等待这一次扫描，直接发布半份缓存。
新增共享监听扩大了事件抵达窗口。外部目录则不属于全工作区 watcher 的监听范围，
补全私有 watcher 与共享发现缓存之间缺少失效传播。

## 修复

snapshot 在代次变化时最多重试两次；持续修改或取消仍返回 isIncomplete，不无界等待。
清单变更通知携带 URI 和事件种类，内容修改只重建对应正文，不清除未变文件模型。
外部 include watcher 同时使共享路径缓存失效；创建/删除刷新发现，正文修改保留路径清单。

## 教训

- 共享缓存需要共享失效协议；私有 watcher 不能只刷新调用方。
- 测试应覆盖事件抵达异步读取中间的情况，真实宿主可发现模拟环境没有的时序。
- 路径发现、正文解析和工具详细化应分别缓存，不能把同一种失效套在所有层。
