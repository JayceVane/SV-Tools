# logic-split-instance-prefix

> **发现方式**：用户报告 `cdc_hs_bits` 中第一个 `cdc_1bit` 例化未对齐，第二个正常。
> **定位耗时**：约十分钟。
> **修复位置**：`src/native/src/formatter/blocks.rs` / `align_pending_instance`。

## 症状

```systemverilog
// Signal declarations

cdc_1bit #(          .CDC_LEVEL (CDC_LEVEL)
    ) u_cdc_req2b_a (
    .i_clk   (i_clk  ),
    .i_rst_n (i_rst_n)
    );
```

整文件格式化保留上述端口空格和错误的结束括号缩进。删掉前置注释或直接选中实例，
端口可以正确对齐；同一文件中参数头没有换行的第二个实例也正常。

## 排查过程

1. 使用原生完整管线复现，单独实例可对齐，添加前置注释后失败；未出现字符保全拒绝日志。
2. 结构识别会清理注释并匹配完整缓冲区，已经进入Instance状态；问题不在端口测宽。
3. `align_pending_instance` 为保留前置文字而逐行寻找实例起点，但只把该物理行传给识别式。
   第一行缺少参数右括号、实例名和端口开括号，后续行又缺少模块类型，因此全部不匹配。
4. 起点回退为0，带注释的缓冲区交给只接收实例的布局器；无法从注释读取模块类型，保守返回。

## 根因

两个阶段使用同一识别式，却传入不同长度的文本：结构分类允许跨行，起点定位只有一行。
识别得到完整构造不等于每一物理行都足以重复识别该构造。用户看到的漏对齐是起点回退的结果。

## 修复

仍逐行枚举候选起点，但匹配 `&code[offset..]` 的完整后缀，跳过非实例关键字。
词法掩码保持字节偏移，输出从原文切片，前缀注释不交给实例布局器。未放宽字符保全守卫。

完整用户语料加入 `example/ex19_split_instance_parameters.sv` 与对应golden；
Rust最小回归及NAPI合同覆盖行/块注释、LF/CRLF、Tab、参数分行、关闭端口对齐和关闭紧凑。
所有输出仍验证非布局字符序列与幂等性。

## 教训

- 定位跨行构造的起点时，应从候选位置检查完整构造，不能用单独一行代替。
- 区分识别失败、布局器保守返回和字符守卫拒绝，避免修改正确的安全边界。
