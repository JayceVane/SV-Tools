# perf-cursor-broadcast-subscription

发现于M4第二阶段完整回归。新增电路读值时，最初在波形`queueValues()`入口无条件广播A/B游标。
该入口也会在调整行高、排序、分组或改变可见集合时执行，原有值查询键虽能去重，新增广播已提前发送。
六项既有交互/手势合同因此失败，包含期望`window,values`却多出`circuit-cursors`的记录。

修复将发布责任放回独立`circuit-link-client.js`：只有实际存在电路观察信号时，宿主才订阅游标，
首次订阅主动报告当前A/B，后续按时间对去重；移除最后一项或映射失效后停止订阅。
`cursor-values.js`还合并查询期间的待办快照，A/B一组返回后原子发布，不逐个游标事件排队。

旧交互测试保持原断言，新增真实客户端订阅/退订回归；调整行高、排序和分组不再广播相同时间。
这次问题说明数据查询入口并不等同于用户改变游标的语义入口，新增消费者需要明确订阅和释放所有权。
