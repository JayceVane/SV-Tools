# compat-package-legacy-native-cache

> **发现方式**：在已有主工程目录构建本地安装包时，检查vsce实际文件树发现异常体积。
> **定位耗时**：本轮约数分钟。
> **修复位置**：`.vscodeignore`、`scripts/check-public-package.js`、`test/public_package_test.js`。

## 症状

实际打包文件树出现：

```text
src-rust/ (12173 files) [4732.84 MB]
svtools.win32-x64-msvc.node [23.12 MB]
```

这些是旧目录迁移后留在本机的Rust构建缓存及根目录旧二进制，正常运行资源已经位于`bin/`。构建在交付前停止，未上传这份临时产物。

## 排查过程

1. 工作区Git状态干净，最初预期vsce文件表与干净CI一致。
2. 对比文件树发现旧`src-rust/target`仍在磁盘，其Git忽略规则来自本地info/exclude；清单只排除了新`src/native/`。
3. 检查`.vscodeignore`确认未显式排除旧目录和根目录旧模块，vsce文件表因此包含这些Git未跟踪文件。
4. 只清理本任务复制出来的失败staging，不删除原始缓存；先修正真实文件表，再重建。

## 根因

Git可提交范围和VSIX可分发范围由不同规则控制。干净CI没有旧缓存，因此单看CI成功或Git状态不能发现已有开发目录的夹带。仅排除当前源目录不足以覆盖迁移遗留物。

## 修复

显式排除`src-rust/**`及根目录`svtools.*.node`，保留正常`bin/*.node`。同时排除本地私有源目录；公开prepublish检查vsce实际清单，发布上传前检查最终VSIX。私有路径、旧缓存路径及根目录原生模块一旦出现则失败。

复制/压缩前按普通文件统计总量，当前限制4096文件、256 MiB未压缩内容；最终归档同样限制文件数与未压缩体积。预算只作为异常夹带检查，后续合法资源增长需要显式评估调整。

新增合同覆盖私有代码/命令/配置/入口、旧路径、根目录二进制、容量边界、越界路径和损坏归档。首次复核的主工程公开文件表为456项、106922079 bytes；最终VSIX验证另记录在本轮交付日志。

## 教训

### 4.1预览复核：本地会话资料

beta.4打包前实际文件表再次发现`.zcode/plans/`中的本地计划。Git忽略规则已经生效，
但VSIX文件表仍包含该目录。新增`.zcode/**`和`.vscode-test/**`分发排除，并让文件表与
最终归档检查同时拒绝这两类路径；合同覆盖大小写、归档前缀和非JS文件。
只修正规则与检查，没有读取或删除会话正文。

- 开发目录迁移后，应检查实际打包文件表，尤其是旧源目录、target和根目录二进制。
- Git忽略、分发排除和最终产物验证各有职责，不能互相替代。
- 压缩后的大小无法防止误复制大缓存，预算检查必须发生在staging复制之前。
