# perf-circuit-trace-fanout-budget

> **发现方式**：M3的3,000端点高扇出用例及真实768扇出Slang夹具。
> **修复位置**：`src/circuit/trace.js`的端点入队和未知方向端点收集。
> **修复提交**：随4.1 M3提交。

## 症状

查询报告达到128单元预算，但仍收集了数千个端口选择。局部投影根据这些选择恢复所有端点单元，可能出现`局部视图端点超过512单元，请收起部分分支`，无法展示本来可以保留的部分结果。

修复前新回归实际失败于：

```text
assert.ok(result.selections.filter(item => item.cellId).length <= 256)
```

未知/双向端点的同类用例也失败。

## 根因

原查询先遍历网络所有端点并写入选择集，等端点出队时才调用`recordCell`检查单元数。查询的单元集合有界，决定绘制规模的端口选择集却已经越过同一预算。

## 修复

端点入队之前先登记/检查所属单元；未知方向端点也执行相同检查。达到预算就停止收集该网络后续端点，保留已有选择、网络真实总驱动/负载数及`cell-budget`原因。原预算没有提高。

纯模型回归保留网络总扇出3,000；真实Slang夹具共有768个单元，局部图保留128单元、131节点和257连线，并明确提示容量截断。界面显示中文原因，不展示停止位置的内部对象ID。

## 教训

预算必须限制产生资源的阶段。仅约束最终遍历集合，不能保证此前收集的端点、选择或待绘制对象同样有界。
