# M3 架构端点与输入身份

状态：已复现并修复，回归位于 `test/design_review_test.js`。

默认视图曾保留完整端口，却使用实例级 `interfaces[]` 聚合并任选代表端口接线。两节点各有请求/响应端口时，反向响应被压到请求端口，图中只剩一条双向线。现在从 `graph.edges` 映射精确显示端口，只有确实落在同一折叠端口的成员才合并。完整源端口的相同信号允许扇出；部分切片不共用主干。边界接口表每行保留原端口身份；顶层 inout 增加精确 bindings，防止表格聚合后丢线或接错行。

`buildArchitecture` 曾按传入文本计算源码哈希，但 WASI 直接挂载实时源码目录。提供 8 位文本、磁盘上改成 4 位时，会得到 4 位模型却绑定 8 位文本的哈希。现在复用 lint 的输入快照：Yosys 读取捕获文本及重写后的字面量 include，源码位置映射回原文件；CLI 返回前复查上下文。未捕获的初始化数据不从实时文件补读，宏 include 保留不支持错误。

生成器曾把省略方向当作 input，并允许遗漏端口和多驱动规格通过。现在方向必须显式指定，连接遗漏、已知方向的多驱动和无驱动输入在落盘前报错，有意悬空需显式 null。Skill 将 master/slave 角色与物理方向分开，允许整体 inout 虚拟接口；成员内容及收发约定写入架构文档，不把反向成员当作已验证的单向 output。

图形验收从单个夹具的固定宽高比，改为精确端点、标签留位、节点和标签不遮挡、画布边界及确定性检查。不同标题或折叠参数使用独立产物名，防止导出相互覆盖。

复现检查：`node --test test/design_review_test.js test/design_render_test.js test/design_arch_test.js test/design_scaffold_test.js`。四个新增根因用例曾在修复前失败；当前增加字面量 include、显式悬空、独立导出及 DDR 双向行的回归。测试中的可选外部演示工程先复制到临时工作区，不写用户原工程。

接口级表达更正：架构阶段不应强制把整体 inout struct 拆成请求/响应。共享网络的未知方向连接现在仍保留为整体接口；默认 `detail=interfaces` 把模块与边界接口表合成一个虚拟端点、一条汇总线，逐成员方向用表内箭头表达。原始方向/位宽/连接保留在 JSON，`detail=signals` 用于精确引脚排查。此前“每行单独布线”的验收只适用于信号级视图，不是架构图的默认要求。
