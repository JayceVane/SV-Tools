# logic-simulation-engine-menu

> **发现方式**：检查标签页“仿真…”菜单的注册与派发流程。
> **定位耗时**：本轮定位，未单独计时。
> **修复位置**：`src/toolchains/simulation-engines.js`、`src/vivado/index.js`。

## 症状

原菜单根据固定数组显示，并将非Icarus选项一律派发给Vivado。菜单条目和执行分支分别维护，扩展候选列表时可能出现错派。

## 排查过程

1. 从标签页按钮的`svtools.simulate.pick`命令追踪，确认它仍使用Vivado组合层内的固定数组。
2. 既有宿主测试直接调用独立命令，无法发现菜单接线遗漏。
3. 补命令接线合同：内置列表和取消用例通过，使用测试引擎的注册用例在原实现失败：

```text
TypeError: h.api.registerSimulationEngine is not a function
```

## 根因

工具能力和统一入口分别维护，扩展命令的存在不代表按钮的候选列表与派发已接通。固定数组及二分派发还会把将来的第三个选项误送入已有工具。

## 修复

将菜单数据和执行回调放到会话级注册器。组合层注册内置引擎并持有注销句柄；注册器只负责列表与派发，不探测工具安装位置。

选择使用注册快照。取消、未知ID、注销或等待期间同ID重新注册都不运行任何工具；正常执行返回原回调结果，失败继续向调用方传播。

新增测试覆盖内置列表、注册/注销、命令派发和生命周期。宿主验收应从实际统一菜单选择引擎；独立命令通过不能替代按钮入口验收。

## 教训

- 新增后端要覆盖用户实际使用的入口，分别检查独立命令与统一选择器。
- 选项与派发应来自同一注册来源，避免名称可见但执行分支缺失。
