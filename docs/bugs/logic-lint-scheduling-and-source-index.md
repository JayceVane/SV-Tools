# Lint 调度、依赖诊断与源码索引

2026-10-30，状态：已修复并通过回归。适用于 4.1.0 的 Icarus / xvlog 检查入口。

## 识别特征与证据

- 输入后在防抖到期前执行停止，编译器仍启动；同样的防抖也会打断刚启动的手动检查，产生第二次编译。
- 仅修改 Vivado 配置即可取消进行中的 Icarus 仿真；即使所有自动检查开关关闭，配置变化仍触发 lint。
- 默认 `currentFileOnly=true` 仍把依赖文件的诊断写入 Problems；编辑依赖后，其他触发文档持有的旧错误没有一起撤销。
- 使用真实 source catalog、3000 个内存源码路径并发冷扫描两次：文件发现 1 次，旧索引同步读取正文 6000 次。清单层去重并不能避免解析层的重复工作。

前三类问题由编辑器事件桩和真实 Node 协议子进程复现；修复后另用解包 VSIX、隔离 IDE 宿主和真实 Icarus 验证停止、手动/自动去重及依赖诊断。没有以协议夹具代替实际 Vivado 厂商工具验收。

## 根因与处理

`iverilog-controller.js` 的定时器、显式命令和配置失效各走一条路径；配置变化使用 `cancelAll`，影响范围超出 lint。现在 `lint-scheduler.js` 统一消费挂起定时器，按文档版本复用自动检查；配置失效按资源、引擎和配置键执行，保留进行中的仿真。

原诊断仅按触发文档持有。现在 `lint-diagnostics.js` 保留所有权，同时建立物理文件到诊断和依赖根的反向索引。源码修改撤销相关结果，保存后依据自动检查配置重检；发布检查依赖变更代次，防止编译中途变化的结果重新出现。当前文件模式只过滤展示范围，依赖失败仍在主文件提示并附完整日志。

不能把“同一文件检查成功”当作删除其他上下文诊断的依据：宏和编译参数不同可能使两次结果都有效。回归测试继续要求不同 owner 的有效结果并存，只有实际源码失效或 owner 关闭才撤销。依赖登记来源是本次显式编译源和诊断涉及文件，尚不是完整的 HDL 预处理 include 图。

`workspace/sources.js` 增加同代次扫描共享、8 路异步读取和有界文件事实缓存。内容未变时复用设计单元名称，代次变化时丢弃迟到扫描；并发读取后仍按发现顺序合并，避免重复单元的优先级随 I/O 改变。刷新重新发现和检查文件元数据，不重复读取未变化正文。元数据签名使用 size / mtime / ctime，依赖正常文件系统的变化通知及元数据更新。

实际 Qoder 宿主复验还发现一次保存并切换编辑器会连续触发上下文和文件事件，两次重试都可能失效，返回 `源码索引在扫描期间持续变化，请稍后重试`。任务没有进入编译阶段，不能归因于 HDL 语法。最小回归以单个等待者连续失效两轮，修复前稳定失败。现在共享整条刷新链，失效重试串行进行；重试前等待25ms合并事件，最多尝试4轮，持续变化仍明确报错，恢复稳定后可重新获取。额外等待仅发生于失效重试，不影响正常缓存命中。

## 验证与复发预防

- `node --test test/lint_diagnostics_test.js test/toolchain_task_test.js test/workspace_test.js test/source_catalog_test.js test/toolchain_test.js`：覆盖停止、手动 xelab 优先、配置隔离、两种引擎的当前文件模式、依赖变化与迟到发布、路径大小写、诊断列去重和扫描失效。
- 3000 文件的双并发冷扫描正文读取从 6000 次降为 3000 次；暖缓存不读取正文。测试同时限制最多 8 路读取、验证刷新只读变化文件和失败后重试。这里是工作量指标，不是实际磁盘或 EDA 编译提速百分比。
- `test/vscode_lint_host.js` 在隔离工作区使用真实 Icarus，检查 Problems 范围、依赖修复、停止防抖及单次手动编译目录。
- 同一文件成功检查、当前文件零错误和整个编译任务成功须继续分别判断。已有任务独立目录、取消信号、进程上限、诊断预算及日志保留保持有效，参见 [工具链成功与产物所有权](logic-toolchain-false-success-and-shared-artifacts.md)。
