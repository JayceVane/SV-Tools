# logic-circuit-refresh-source-stale

> **发现方式**：M3在实际Qoder解包宿主中检查Webview，刷新和源码定位已通过，但界面仍提示源码过期。
> **修复位置**：`src/circuit/index.js`快照交接、`host.js`面板来源状态。
> **修复提交**：随4.1.0-beta.2候选提交。

## 症状

真实界面保留：`源码已变化，当前图仍对应生成快照；请刷新后再定位源码`。

此时新模型已经按未保存正文重新生成，直接源码定位也通过内容指纹检查；界面仍将源码按钮视为过期而禁用。beta.1因此没有作为最终交付包。

## 根因

编辑事件被观察器延迟200ms合并。刷新先清除面板过期标记，再异步解析起点和准备输入；旧观察器的待处理事件可能在这个窗口触发，重新写入过期标记。随后观察器替换为新快照，但只重置自身状态，没有清除已写入面板的旧标记。

## 修复

可信生成入口捕获新快照时，同时清除面板旧标记并替换观察器。交接仍校验当前加载信号未取消，旧生成请求不能清除新请求的状态。新快照之后发生的编辑仍能重新置为过期。

增加确定性宿主回归：刷新挂起时注入旧通知，捕获新快照，再完成加载，断言新图的`sourceStale`为false；再注入当前编辑则仍为true。真实IDE验收额外断言刷新后的来源状态，避免只检查模型跳转成功而漏掉界面状态。

## 教训

替换延迟观察器时，需要一并交接它已经写入外部所有者的状态。后端验证成功，不能代替界面可执行状态验证。
