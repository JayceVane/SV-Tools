# logic-circuit-trace-screen-anchor

> **发现方式**：M3在实际浏览器中展开时序边界，读取同一起点的屏幕位置。
> **修复位置**：`src/circuit/client.js`的连续换图相机与视口测量。
> **修复提交**：随4.1 M3提交。

## 症状

第一次展开新增“已展开分支”行后，起点从屏幕Y=723.5移动到751.5，偏移28像素。单元图坐标和缩放补偿本身正确，原有Fake DOM回归也通过。

## 排查与根因

原相机只补偿ELK起点图坐标的差值，视口位置则在追踪栏更新之前测量。新增一行追踪控件后，SVG在页面中的顶部位置改变，起点虽然保持SVG内部坐标，屏幕坐标仍发生位移。

原Fake DOM固定返回画布矩形，因此没有覆盖真实页面的重排。

## 修复

换图前记录旧画布矩形；先更新追踪控件，再测量新矩形。连续展开/收起的相机同时补偿图坐标差值与视口`left/top`差值。

新增回归让画布顶部随展开栏行数变化28像素，验证相机反向补偿。实际浏览器复验起点X保持662.5，Y从717.5到718.5，剩余1像素属于该页面几何取整范围；没有承诺所有ELK节点坐标固定。

## 教训

屏幕锚点由模型坐标、相机和页面布局共同决定。仅固定其中两者，不能保证界面重排时的视觉连续性。
