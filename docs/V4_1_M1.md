# 4.1 M1：位级拓扑与局部追踪

日期：2026-10-25。开发分支：`codex/feat-v4.1-signal-tracing`。

本轮交付查询层和Worker接口，落实[4.1计划](V4_1_PLAN.md)的M1。源码右键追踪、局部图布局、连续展开、导航和关注对象由M2接入；当前扩展及CLI仍为4.0.0，未生成4.1安装包。

## 技术方向与当前结果

追踪读取工具无关的领域模型，按模块局部位ID、真实端口方向和原始位位置建立拓扑。它不读取页面布局图，也不从信号名猜测连接。原有总线展示和同值常量符号可用于绘图，但不作为追踪的连接依据。

模块端口的声明方向保持不变：输入在模块内部是驱动端，输出是负载。位数组继续使用LSB-first，`offset`和`upto`只解释HDL下标。复制位保留每个端口位置；常量按具体对象和位置停止，不合并同值常量的物理连接。

实现分为三部分：

| 模块 | 职责 |
|---|---|
| `src/circuit/topology.js` | 位端点索引、常量隔离、声明下标和位位置换算 |
| `src/circuit/trace-semantics.js` | 单元内结构位映射，以及显式保守候选范围 |
| `src/circuit/trace.js` | 单次查询状态、预算、边界、实例上下文和会话内索引缓存 |

`worker.js`拥有追踪器；重载释放旧索引，关闭会话终止Worker。查询发生在完整模块布局之前。3,000单元的回归同时验证了完整布局超预算和局部选定位查询成功。

## 查询合同

`createCircuitTracer(design)`接收已由`createDesign`验证且保持不可变的模型，提供`listSignals`、`trace`、`stats`和`dispose`。索引按需构建；查询结果不缓存，每次请求独立拥有队列和结果集合。

Worker提供两个新命令：

```js
const descriptor = await session.request('load', loadOptions);
const snapshot = {
    designId: descriptor.id,
    revision: descriptor.revision,
    moduleId: descriptor.top
};
const candidates = await session.request('traceSignals', {
    ...snapshot, query: 'o_valid', limit: 200
});
const result = await session.request('trace', {
    ...snapshot,
    direction: 'drivers', // 或loads
    origin: { objectId: candidates.items[0].objectId, positions: [0] },
    depth: 1
});
```

示例中的候选应由调用端确认；多候选不能自动选择第一个。`objectId`可对应模块端口、信号别名或具体单元引脚。`positions`表示原向量中的LSB-first位置；也可改用`indices`指定HDL声明下标，两者不能同时提供。省略时选择整条向量，超过4,096位时要求显式选择切片。

`designId`保持现有内容身份；新增`revision`区分同一JSON的再次加载。两个新Worker命令都要求身份和世代匹配。相同文件重新加载后，旧追踪请求仍会被拒绝。直接使用纯查询API时，由调用者拥有并销毁对应设计会话。

省略`instancePath`表示模块定义查询，结果明确标记`module-definition`。若提供从设计top开始的单元ID数组，查询逐层验证真实`moduleId`，并标记实例上下文。实例边界仅在名称、位宽和方向一致时返回可继续使用的子模块端口位置映射。M1不自动跨层扩展。

## 精度和停止边界

`nets`描述实际位连接，`transitions`描述单元内部沿追踪方向的遍历关系。`precision: "bit"`表示已支持的结构位映射，不证明布尔可敏化性、时序正确性或源码语句等价。`precision: "cell"`表示包含保守候选；单个transition记录局部精度，selection也保留经过保守路径的信息。

当前精确映射支持等宽`$pos/$not`、常见按位逻辑及对应基本门、`$mux`、`$concat`和`$slice`。不等宽扩展、复杂算术及未支持的组合运算保留单元级候选输入/输出，不冒充精确依赖。

| 边界 | 行为 |
|---|---|
| `sequential` | 默认在寄存器停止；已确认的时钟、复位、使能及极性复用既有符号语义 |
| `crossSequential: true` | 显式越过时序边界，标记为跨时序的保守候选；保留已知引脚角色 |
| `instance` / `blackbox` / `memory` | 保留边界及已有的明确映射，不猜测内部行为 |
| `unknown-direction` | 标出未知或双向端点，不将可能存在的驱动误报为无驱动 |
| `multiple-drivers` | 保留所有已知驱动及总数，不静默选择其中一个 |
| `undriven` / `unloaded` | 无已知方向歧义时，明确标出缺驱动或无负载 |
| `loop` | 依据当前祖先路径终止组合环路；普通重汇合只复用访问结果，不误报环路 |
| `constant` / `module-port` / `depth` | 正常窗口边界；常量同时保留具体值及位置 |

默认深度1允许跨过一层单元内部关系，下一层的边界单元仍可出现在结果中，`expanded`区分是否已展开。`nets.endpoints`只含窗口内涉及的端点，原网络的驱动、负载及未知方向总数另行保留，不能把窗口外端点视为断路。

## 容量与缓存

模型总预算保持原有2,000,000位引用；追踪索引另外限制单模块及缓存总量为500,000端口位引用和100,000对象，最多缓存四个模块，按LRU淘汰。索引超预算明确失败，要求选择子模块；不提高既有全图布局上限。

| 查询预算 | 默认 | 可配置上限 |
|---|---:|---:|
| 自动跨越深度 | 1 | 32 |
| 单元 | 128 | 2,000 |
| 已安排访问的位端点 | 8,192 | 16,384 |
| 网络位 | 4,096 | 8,192 |
| 单元内部位转换 | 8,192 | 16,384 |
| 工作计数 | 50,000 | 200,000 |

边界组最多512个。容量截断保留已发现结果，返回`truncated`及`truncationReasons`；正常的深度、时序和模块边界与容量截断分开表达。关闭时拒绝挂起请求并终止Worker；M1未增加逐请求暂停接口。

## 验收与测量

- `circuit_trace_test.js`覆盖位选择、方向、切片、拼接、复制、常量、MUX、时序、未知方向、多驱动、环路、预算和LRU。
- `circuit_trace_session_test.js`使用真实Worker验证超布局预算的局部查询、索引复用、重载世代和关闭时的挂起请求。
- `circuit_trace_native_test.js`运行固定内置Yosys/Slang，核对公开RTL夹具的原始位关系；Vivado使用平坦导出合同夹具验证查询边界，未将该夹具称为本轮真实Vivado生成。

Slang为两个实例生成了各自的模块ID，验收沿真实实例引用定位模块，没有按源码模块名回退。公开夹具为`test/fixtures/circuit-trace.sv`，实际JSON及结果保存在`bin/circuit-trace-native/`。

性能基准是明确标记的合成领域模型：20,000个独立反相器、80,000端口位引用、40,000网络位。测量同进程的索引和纯查询，不含Worker消息序列化或传输。模型生成和GC不计入查询；5次冷请求、10次预热、100次热请求。每次只选择一个输出位，局部结果为一个单元。Node24.17.0、Windows x64，运行时使用`--expose-gc`。

测量前目标为索引/冷查询p95不超过1,000ms、热查询p95不超过10ms、索引堆增量不超过128MiB。测量报告为`bin/circuit-trace-benchmark/report.json`；本机观测索引约46ms、冷查询p95约42ms、热查询p95约0.018ms、索引堆增量约27.6MiB。该结果不代表密集高扇出设计、局部布局或SVG交互性能；M2再加入这些测量。

复验入口：`node --test test/circuit_trace_test.js test/circuit_trace_session_test.js test/circuit_trace_native_test.js`，以及`node --expose-gc scripts/benchmark-circuit-trace.js`。完整回归和宿主报告保存在`bin/circuit-trace-*`，最终结果见本轮交接记录。

实现依据：[Yosys JSON位序、offset与upto合同](https://yosyshq.readthedocs.io/projects/yosys/en/latest/cmd/index_backends.html)、[MUX单元模型](https://yosyshq.readthedocs.io/projects/yosys/en/stable/cell/word_mux.html)。复杂运算未由这些映射证明时继续保守处理。

M2从结果投影与追踪入口开始，保持真实位映射、稳定导航、世代检查和既有源码路径校验；随后进入P0真实宿主验收。
